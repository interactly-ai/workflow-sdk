classifier from the root `pyproject.toml`, with a comment recording why. Install now succeeds.

## Gate 3 — `make lint` ❌ 1117 errors → ✅ GREEN

`ruff check src/ tests/` reported **1117 errors**. The breakdown mattered more than the number:

| Rule | Count | Nature |
|---|---|---|
| `UP045` non-pep604-annotation-optional | 544 | style |
| `UP006` non-pep585-annotation | 328 | style |
| `UP035` deprecated-import | 81 | style |
| `UP037` quoted-annotation | 66 | style |
| `UP007` non-pep604-annotation-union | 2 | style |
| **`UP` subtotal** | **1021** | **style only** |
| `F401` unused-import | 50 | real |
| `I001` unsorted-imports | 28 | real |
| `N814` camelcase-imported-as-constant | 11 | intentional pattern |
| `F841` unused-variable | 3 | real |
| `E402` module-import-not-at-top | 1 | real |
| `F821` **undefined-name** | 1 | **real latent bug** |

### Decision: `UP` (pyupgrade) removed from the selected ruleset — please review

91% of the findings were pyupgrade rules that would rewrite `Optional[X]` → `X | None` and
`List[X]` → `list[X]`. **Enforcing them would actively sabotage the sync strategy.**
`configs/src/interactly_configs/` is a deliberate mirror of `agentic_workflow_framework/configs/`,
which uses the typing-module style — the two currently agree *exactly* (both have 43 `Optional[`
occurrences in `llm.py`). Auto-upgrading would permanently diverge the mirror from upstream and turn
every future sync from a diff into a manual reconciliation, which is precisely what plan principle #2
exists to prevent. `src/interactly/` is kept in the same style so both halves read alike.

`make lint` only covers `src/ tests/` today, so `configs/` was never at risk from the Makefile — but a
plain `ruff check .` would have been enough to do the damage. The ruleset now says so explicitly.

`N814` was also globally ignored: all 11 sites are the same intentional pattern — `interactly.types.*`
models importing config classes lazily inside functions and aliasing them short (`EdgeConfig as _EC`)
to keep `interactly_configs` optional and avoid import cycles. One documented ignore beats 11 identical
`noqa`s.

### Real fixes applied

- **`F821` — genuine latent bug.** `_utils/_retry.py:145` annotated `with_retry_async`'s `send`
  parameter as `"asyncio.Coroutine[...]"` while `import asyncio` sat *inside the function body*. The
  quoted annotation plus `from __future__ import annotations` meant it never raised at runtime, but the
  annotation was unresolvable for `typing.get_type_hints`, mypy, and any doc tooling. Moved the import
  to module level and removed the redundant local one.
- `F401` ×49 — genuinely unused imports, auto-fixed. Verified first that **none** were in an
  `__init__.py`, so no re-export was broken.
- `F401` ×1 — `configs.py:214` is an intentional optional-dependency availability probe inside
  `try/except ImportError` that appends to `__all__`. Given a `# noqa: F401` and an explanatory comment.
- `I001` ×28, `W293` ×2 — auto-fixed.
- `E402` — `_types.py` imported `TypeVar` in the middle of the file for no reason; folded into the
  top-level `typing` import.
- `F841` ×3 — unused `route = respx.post(...)` locals in two test files; assignment dropped.

**Result: `All checks passed!`, with `make test` still at 364 passed.**

## Gate 4 — `make typecheck` ❌ config error → ❌ 79 real errors (now honestly measurable)

Originally mypy aborted before checking anything:

```
src/interactly/types/edges/edge.py: error: Source file found twice under different module names:
"src.interactly.types.edges.edge" and "interactly.types.edges.edge"
Found 1 error in 1 file (errors prevented further checking)
```

Cause: stray empty `src/__init__.py` and `configs/src/__init__.py` made `src` look like a package, so
every module resolved under two names. Both files were empty, referenced nowhere, and irrelevant to
packaging (hatch builds `src/interactly` and `src/interactly_configs` directly). **Removed.**

Worst-affected: `runtime/handle.py` (15), `resources/tools/tools.py` (12), `_streaming.py` (9).

## Security finding — `.env` was tracked in git ✅ FIXED

`workflow-sdk/.env`, containing `INTERACTLY_API_KEY`, was **tracked and committed** (commits `a266b5d`,
`af22255`). `.gitignore` covered `.envrc`, `.venv`, `env/`, `venv/` — but not `.env`.

**Severity is low, and verified so rather than assumed:** the committed value is the *old* 288-char JWT,
and it returns **401** against dev today. No live credential is exposed in git history.

It was still a live leak *vector*, and Phase 0 was about to write the current working key to exactly
that path. Fixed before doing so:

1. `.env`, `.env_dev`, `.env_qa` added to `.gitignore` with a comment naming the two prior commits.
2. `git rm --cached .env` — untracked, file preserved on disk.
3. Added a committed **`.env.example`** with the four required keys and empty values.
4. Copied the working `../.env_dev` into `.env` and verified `200` against dev.

**No history rewrite performed and no credential rotated** — both are your call, and neither looks
warranted given the committed key is already dead. Flagging so the decision is yours, not mine.
